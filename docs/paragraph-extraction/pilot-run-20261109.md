# Operative activity pilot — execution record

The user authorized testing the Azure deployment and proceeding if it worked.
GPT-6 Luna responded successfully with reasoning disabled. The fixed random
sample is 374 of 3,736 eligible Mandate Registry documents: recent documents
from 2021-11-09 through 2026-11-09 plus PPB2027 programme-budget-cited resolutions
of any age. The Digital Library outside registry scope is excluded.

The run has **8,299 logical operative targets**. Stored operative flags account
for 8,131; a documented source-boundary review of the 45 zero-target documents
adds 168. True preambles, footnotes, article headings and membership rosters
are excluded from these additions. The source snapshot and sample were retained;
no production paragraph flags were updated.

## Diagnostic review

The first 100 requests produced 94 schema/evidence-valid replies. The revision
encodes the category hierarchy in schema, strengthens actor/mention guidance,
and handles Responses final-answer messages separately from commentary.
The same 100 diagnostic cases then validated 100/100. All reported reasoning
tokens were zero. They used 534,156 input tokens (493,822 cached) and 23,372
output tokens. These 100 responses are reused in the sample; the remaining
8,199 requests were started.

**Technical validity is not semantic accuracy.** Source review found missed tasks,
actor classification/name inconsistencies, overly broad mentions, and uncertain
splitting of activities. This is an exploratory dataset for further analysis,
not a production import. The diagnostic cases informed prompt revisions and
are not a held-out evaluation. Quality preservation relative to the old model
has not been established. Specific issues and reviewed request IDs are in
[pilot-smoke-review-20261109.json](pilot-smoke-review-20261109.json).

## Branch website preview

`SHOW_PARAGRAPH_PILOT` in `website/src/lib/feature-flags.ts` enables the preview.
The explorer's “Sampled resolutions only” switch uses `pilot_sample=1`, through
the shared URL parser and server query predicate. The frozen sample has 282
resolutions; other sampled document types remain accessible directly but are
excluded by this switch. Grouping and other active filters can reduce the row
count. Search, pagination, counts and exports share the sample restriction.

`export_website.py` exports the validated results and rejection status to
`website/src/data/paragraph-pilot.json`, with the resolution symbol list in
`paragraph-pilot-sample.json`. Reproduce from the repository root:

```bash
/tmp/mandate-budget-20261109/bin/python \
  data-processing/evals/paragraph_entities/export_website.py
```

Only server code reads the full artifact; detail pages receive their own
paragraph annotations. UUID, text SHA-256 and parser-version checks gate every
attachment. Python evidence offsets are converted to JavaScript UTF-16 offsets.
The original fulltext, links, footnote references and deterministic action verbs
are preserved. No database writes are involved. Changed sources and rejected
responses are marked unavailable and do not expose heuristic entity results.

Both full-page and sheet views use the same paragraph component. Activity
family/subtype filters and entity type/name filters accompany the grouped action
verbs and output filters. Evidence highlights support overlaps and expose
classification tooltips; per-paragraph category chips also select their activity
filter. The original `SHOW_PARAGRAPH_ENTITIES` flag remains false for other
paragraphs. The preview remains exploratory, with the semantic limitations above.

### Preview contrast and hierarchy review

Paragraph cards now use white backgrounds and distinct sky, emerald, amber and
violet evidence fills. Literal verbs have a single deterministic action tooltip;
activity tooltips are suppressed within that verb span. Dropdowns no longer sit
inside help-tooltip triggers. Pilot documents display Activities, Entities and
Action verbs; the legacy Deliverables filter is omitted there.

The six agreed activity families have readable labels. Substantive branches by
UN-system, Member-State and other/unspecified implementers, then delivery subtype.
Each activity retains its own actor types, so a separate SG reporting task cannot
misattribute Member-State substantive work. Counts deduplicate paragraphs across
multiple activities. Institutional labels include mandate establishment, renewal,
change, termination, and appointments/membership.

Independent source and screenshot review found and corrected a With-entities
filter-key mismatch. Browser checks verified that filter (102 matches for
A/RES/78/245), implementer selection, one verb tooltip, no open-menu help tooltip,
and desktop/mobile hierarchy layouts. Reviewer found no remaining blocking
correctness or visual issue. Existing page-wide mobile overflow comes from the
footer; the paragraph menu fits the viewport.

### Assigned actors only in the frontend

The display now projects entity annotations to assignees only. Mentioned actors
and affected institutional targets do not receive separate entity highlights,
and mentions do not contribute to the Assignees filter's types, names or counts.
Activity/output evidence remains visible. Stored extraction records still retain
both roles unchanged. Browser verification on A/RES/78/245 found zero mention
highlights, 89 assignee spans, and 81 paragraphs in the With-assignees facet.

### Task wording and shared filters

The UI now calls extracted activities “Tasks” (stored schema codes unchanged).
Tasks, Assignees and Action verbs share `ParagraphFacetFilter`, including search,
selected-state styling, hierarchy rendering and the All-paragraphs reset. Verb
highlighting uses text weight/color only, with an underline for a selected verb.
Tooltips separate task type and explanation, assigned actor and actor type, and
expected output. Verb tooltips explain their speech-act category in plain language.
